## How I Work

I usually start with two questions:

1. What does the system need to accomplish for the business?
2. What is actually happening at the protocol, device, service, or workflow level?

That combination tends to produce simpler architectures, better diagnostics, clearer documentation, and fewer mysteries at 2:00 AM.
